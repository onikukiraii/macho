# 初期データの seed

空の DB へ、種目、トレーニングマックス、プログラム、過去のトレーニング記録をまとめて投入するためのデータ。このディレクトリのファイルは一例で、同じ形式のファイルに置き換えれば自分の初期データを投入できる。投入の手順は `docs/deploy.md` の手順 3 にある。

6つのファイルがすべて必要。CSV は UTF-8 で、1行目に列名を置く。

## exercise_master.csv

BIG3 と、その派生種目を定義する。

| 列 | 内容 |
|---|---|
| 種目 | 種目名。64 字まで |
| 区分 | 本体と派生種目をまとめる名前。`SQ` `BP` `DL` など |
| 係数 | 本体は `1`。派生種目は本体の e1RM に対する換算係数で、2 以下 |

区分ごとに、係数 `1` の本体を1つ置く。係数が `1` 以外の種目は、同じ区分の本体を派生元にして作られる。セット間レストのデフォルトは 180 秒になる。

## training_maxes.csv

BIG3 の本体のトレーニングマックスの初期値。1行が1種目。

| 列 | 内容 |
|---|---|
| 種目 | `exercise_master.csv` で係数 `1` の種目名 |
| トレーニングマックス | kg。500 まで |

記録の画面で本体と派生種目の目標重量を出すのに使う。値は直近の実績の推定1RM を目安にする。この例の値は、増量期の開始日以降で推定1RM が最も高いセットから求めた。

行の無い種目は目標重量が出ない。投入のあとは、毎週の自動更新か種目の画面での手入力で更新する。

## training_logs.csv

過去のトレーニング記録。1行が1セット。

| 列 | 内容 |
|---|---|
| 日付 | `YYYY-MM-DD`。今日より後の日付は置けない |
| 種目 | 種目名 |
| セット | その種目の中でのセット番号。1 から 50 まで |
| 重量 | kg。500 まで。空欄は 0kg として投入する |
| レップ数 | 回数。100 まで。小数は四捨五入する |

同じ日付で同じ種目の行が続き、セット番号が増えていく間は1つの実施種目にまとまる。セット番号が戻ると、同じ種目でも別の実施種目になる。

`exercise_master.csv` に無い種目名は補助種目として作られ、セット間レストのデフォルトは 90 秒になる。

最後の日付を含む週は、トレーニングマックスの週ごとの自動更新で評価済みとして記録される。

## bulking_phase.csv

投入するプログラム。1行が1つの予定種目。

| 列 | 内容 |
|---|---|
| 週 | 週番号。後ろに空白とラベルを付けられる。`2 デロード` `17 テスト` |
| 目安日 | `YYYY-MM-DD`。プログラムの開始日と週番号と曜日から求まる日付と一致させる |
| Day | `Day1 月` の形。テストの日は `テスト 月` |
| 種目 | 種目名 |
| セット | セット数 |
| レップ | 回数 |
| 目標RPE | 空欄可 |
| 実績重量kg | 空欄可 |
| 実績レップ | 空欄可 |
| 実績RIR | 空欄可 |

ラベルの無い週は、ラベルの付いた週を区切りにして ブロックA、ブロックB と名前が付く。テストの日は、種目ごとに6行を置く。目標は上から 40%、60%、75%、85%、92%、100% になる。

実績の列のどれかが入っている行があると、その目安日の記録がその Day に紐付く。実績の重量、レップ、RIR の3つが揃った行は、同じ日付・種目・重量・回数のセットへ RIR を入れる。

プログラムの名前と開始日は、`backend/scripts/import_legacy.py` の `PROGRAM_NAME` と `PROGRAM_START_DATE` にある。

## cutting_phase.csv

`bulking_phase.csv` と同じ列。プログラムにはならず、実績の重量、レップ、RIR の3つが揃った行が RIR の補完に使われる。補完が要らなければ、列名の行だけのファイルにする。

## design_note.md

プログラムの設計メモ。ファイルの中身がそのままプログラムの設計メモになる。
