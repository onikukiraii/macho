# 機能一覧

[ドメインモデル](./domain-model.md) をもとに、アプリの機能を場面ごとに並べる。場面は [ノーススターストーリー](./north-star.md) の流れに沿っている。

優先度の意味は次のとおり。

- **P0**: KINNIK と xlsx をやめるのに要る。これが揃った時点で乗り換える
- **P1**: 乗り換えたあと早めに要る
- **P2**: データが溜まってから、または運用して困ってから作る

## 1. ジムでのトレーニング

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| T-1 | トレーニング記録の追加 | ホームのカレンダーで日付を選び、+ ボタンでその日付のトレーニング記録を作る。選べるのは今日以前の日付。進行中のプログラムがあれば次の Day を選んだ状態で開く。Day は別のものに変えられ、Day を選ばない予定外のトレーニング記録も作れる。記録済みの Day も選べるので、1つの Day を2回に分けてこなすときにも使う | P0 |
| T-2 | 予定の表示 | 選んだ Day の週の label、目安日、予定種目ごとの目標重量・レップ・セット数、前回実績 | P0 |
| T-3 | トレーニングマックスの更新のお知らせ | 記録を追加したときに前の週の評価で更新があれば表示する。「ベンチプレス 88.0 → 90.5」 | P0 |
| T-4 | セットの入力 | 種目ごとに、列をセット、行を重量・回数・RIR とする表で入力する。行のラベルは置かず、列の見出しをセット番号にする。空のセットを予定のセット数ぶん並べ、予定外の種目では5セットぶん並べる。列は追加できる | P0 |
| T-5 | 目標のプレースホルダ | 予定種目の目標重量とレップを、空のセットのプレースホルダに出す | P0 |
| T-6 | 重量の自動入力 | セットの重量を入力すると、後ろの空のセットに同じ重量が入る。1日の中では決まった重量をこなす前提 | P0 |
| T-7 | 前のセットからのコピー | セットを長押しすると、前のセットの重量・回数・RIR が入る | P1 |
| T-8 | RIR の入力 | 二択変換法の質問を画面に出す。「あと1回、絶対いける？」 | P0 |
| T-9 | レストタイマー | 開始と停止のボタンで動かす。開始すると種目の default_rest_seconds から数える。延長できる | P0 |
| T-10 | レスト終了の通知 | 画面をロックしていても Web Push で通知音を鳴らす | P0 |
| T-11 | プログラム外の種目の追加 | トレーニング中に種目を追加する。種目一覧に無ければその場で作る | P0 |
| T-12 | 予定種目の差し替え | 予定の種目を別の種目でこなす。ラックが空いていないときなど | P1 |
| T-13 | メモ | トレーニング記録と実施種目にメモを残す | P1 |

## 2. 履歴

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| H-1 | カレンダー | ホームに月のカレンダーを置き、開いたときは今日の日付を選んだ状態にする。トレーニング記録のある日に印を付け、日付を選ぶとその日の Day と種目ごとのトップセットを表示する | P0 |
| H-2 | トレーニング記録の編集と削除 | カレンダーから開いて入力ミスを直す。セットの追加・変更・削除、トレーニング記録の削除 | P0 |
| H-3 | 種目ごとの履歴 | 種目を選ぶと、その種目を含むトレーニング記録を新しい順に並べ、各セットを表示する | P1 |

## 3. トレーニングマックス

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| M-1 | 週ごとの自動更新 | 新しい週の最初のトレーニング記録を作るときに、前の週を評価して更新する。画面は持たず、T-3 で結果を出す | P0 |
| M-2 | 現在値と履歴の表示 | 種目ごとの現在値と、いつ・なぜ変わったかの一覧 | P0 |
| M-3 | 手動の変更 | 値と理由を入力して1行追加する。下げるのはこの操作に限る | P0 |

## 4. プログラム

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| P-1 | プログラムの表示 | 週と Day の一覧と、Day ごとの消化状況。消化済み・未実施・未消化 | P0 |
| P-2 | プログラム作成ルールの編集 | Markdown を編集する | P0 |
| P-3 | 生成用プロンプトのコピー | プログラム作成ルール、種目一覧、トレーニングマックス、直近の実績、design_note、JSON の形をまとめてクリップボードへコピーする | P0 |
| P-4 | JSON の取り込みとプレビュー | 貼り付けた JSON を検証し、週・Day・予定種目と計算した目標重量、新しく作る種目を表示する。検証エラーは該当箇所と理由を出す | P0 |
| P-5 | プログラムの確定 | プレビューを確定して新しいプログラムとして追加する | P0 |
| P-6 | 過去のプログラムの一覧 | 終了したプログラムと design_note を見返す | P2 |

## 5. 月次レビュー

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| R-1 | CSV 出力 | 期間を指定して、セット単位の CSV を出力する。日付、Day、種目、重量、回数、RIR、e1RM、予定のレップと目標RPE、目標重量 | P0 |
| R-2 | レビュー用プロンプトのコピー | CSV に加えて、プログラム作成ルール、design_note、トレーニングマックスの履歴をまとめてコピーする。「この重量のままでいいか」をそのまま聞ける形にする | P1 |

## 6. 種目

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| E-1 | 種目の一覧 | 種類ごとに並べる。トレーニングマックスを持つ種目、派生種目、ダブルプログレッションの種目 | P0 |
| E-2 | 種目の追加と編集 | 名前、parent と換算係数、1RM の推定式の分母、上げる幅、レスト秒数 | P0 |

## 7. 分析

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| A-1 | 種目ごとの指標 | 期間を指定して、最大重量、推定1RM の最大値、総ボリューム | P1 |
| A-2 | 推定1RM の推移グラフ | トレーニング記録ごとのトップセットの e1RM と、トレーニングマックスの推移を重ねる | P1 |
| A-3 | 総ボリュームの推移グラフ | 種目別に週ごと・月ごと | P1 |
| A-4 | BIG3 合計 | スクワット・ベンチプレス・デッドリフトの推定1RM の合計と、目標の 400kg までの差 | P2 |

## 8. 基盤

| ID | 機能 | 内容 | 優先度 |
|---|---|---|---|
| B-1 | PWA | iPhone のホーム画面に追加して使う。Web Push の前提 | P0 |
| B-3 | 移行 | KINNIK の CSV と xlsx からの取り込み。画面は持たず、1回だけ実行するスクリプト | P0 |

## 画面との対応

デザインで画面を割るときの出発点。

| 画面 | 機能 |
|---|---|
| ホーム | H-1、T-1、T-3 |
| トレーニング記録 | T-2、T-4〜T-13、H-2 |
| 種目 | E-1、E-2、M-2、M-3、H-3 |
| プログラム | P-1〜P-6 |
| 分析 | A-1〜A-4 |
| エクスポート | R-1、R-2 |

トレーニング中の入力と、あとからの編集は同じ画面で行う。

## 機能にしないもの

- トレーニングの終了操作。トレーニングマックスの評価は次の週の開始時に行うため要らない
- Day のスキップ操作。記録の無い Day は、順番が後ろの Day に記録を付けた時点で未実施になる
- 作成したプログラムの編集。計画を変えるときは新しいプログラムを追加する
- 種目の削除。過去の記録が参照する
- ログイン。自宅の Mac mini で動かし、専用の VPN に接続した端末からのみアクセスする
